## ПР10 — административная панель

Управление данными доступно по адресу http://127.0.0.1:8000/admin/.

```bash
git pull
bash run_web.sh
```

При первом запуске во второй вкладке Терминала из папки проекта создайте
администратора (логин и пароль выбираются при выполнении команды):

```bash
.venv-web/bin/python manage.py createsuperuser
```

Войдите в `/admin/`. В разделе «Файловое хранилище» доступны пользователи
каталога, папки и файлы; в разделе «Права доступа» — права read/write.
Администратор Django и пользователь каталога — разные сущности.
Пароль не хранится в репозитории. Обычный посетитель не может открыть админ-панель;
сотрудникам Django нужны соответствующие разрешения на модели.

Чтобы добавить файл, сначала создайте пользователя каталога и папку, затем
выберите «Файлы → Добавить» и заполните имя, папку, размер в байтах и дату.
Изменения сразу появляются на обычных страницах. Здесь хранятся сведения о файлах;
загрузка содержимого PDF, фото или других документов пока не реализована.

В списках настроены столбцы, поиск, фильтрация и сортировка; в карточках папок
и пользователей отображаются связанные записи со ссылками на редактирование.
Встроенные списки доступны только для просмотра, изменения выполняются
в отдельных формах. Администраторы управляют всеми данными в пределах разрешений
Django. Пользовательские read/write относятся к каталогу и консольным сервисам.

При сохранении файла проверяется общая квота владельца. Квоту нельзя уменьшить
ниже занятого места. Владелец существующей папки в админ-панели не меняется.
Собственное право владельцу выдать нельзя. Обязательные поля, уникальность
и внешние ключи проверяются моделями и базой данных.

Папки получили уникальный slug и get_absolute_url(); прежние адреса по ID
сохранены. Для существующих папок миграция формирует `folder-ID`, для новых —
уникальный адрес. У файла добавлено GeneratedField `is_large`: база вычисляет,
достигает ли размер 10 МиБ. Поле доступно только для чтения и используется
в списке и фильтре административной панели.

Уровни доступа описаны Access.Level (TextChoices), исходные значения read/write
сохранены. Методы AccessQuerySet readable/writable/with_names и FileQuerySet
nonempty/with_owners/uploaded_before используются в приложении.
Контекстный процессор передаёт общее название сайта без дополнительных SQL-запросов.

## ПР9 — модели Django и ORM

Веб-приложение работает через Django ORM. Модели User, Folder и File находятся
в `library/models.py`, Access — в `permissions/models.py`. Общая абстрактная
модель NamedEntity задаёт имя и строковое представление. Связи используют
ForeignKey и related_name; пользователи и общие папки связаны ManyToMany через
Access. Пользователь здесь — сущность каталога, вход в админ-панель использует отдельную модель django.contrib.auth.User.

### Запуск на Mac

```bash
git pull
bash run_web.sh
```

Открыть http://127.0.0.1:8000/. Остановка — Ctrl+C. Скрипт выбирает Python 3.10+,
создаёт `.venv-web`, устанавливает Django 5.2, применяет миграции и переносит данные
ПР7, если целевая база пуста. Повторный запуск сохраняет существующие записи.
Локальный сервер отдаёт статику с `--insecure` при DEBUG=False.

### Ручной запуск

```bash
python3.12 -m venv .venv-web
source .venv-web/bin/activate
python -m pip install -r requirements.txt -r requirements-dev.txt
python manage.py migrate
python manage.py import_legacy
python manage.py runserver 127.0.0.1:8000 --insecure
```

Исходная база ПР7 `data/storage.sqlite` включена в репозиторий и остаётся
неизменной при переносе. Django создаёт отдельную `db.sqlite3`, исключённую из Git.
Другой источник задаётся `python manage.py import_legacy --source /путь/base.sqlite`.
Целевая база задаётся переменной окружения `DJANGO_DATABASE`.
Импорт в непустую базу запрещён; `--if-empty` пропускает такой импорт.
Перенос проверяет исходные данные и выполняется в транзакции: ошибка откатывает
все записи. ID и связи сохраняются; Access получает служебный ID, а пара
пользователь/папка остаётся уникальной. Необязательные email также переносятся.

Консольное приложение по-прежнему использует JSON. SQL-файлы и модули
`db/database.py`, `db/import_json.py` сохранены для работы с форматом ПР7.
Прямой SQL используется только при чтении старой базы для переноса; веб-страницы
получают данные через ORM. Автоматической синхронизации JSON и Django-базы нет.

### Страницы

| Адрес | Содержимое |
| --- | --- |
| `/` | Счётчики объектов и навигация |
| `/folders/` | Папки и владельцы |
| `/folders/<id>/` | Файлы папки и общая квота владельца |
| `/files/` | Поиск, фильтры, сортировка, страницы по 10 файлов |
| `/files/<id>/` | Данные файла, папки и владельца |
| `/accesses/` | Выданные права |
| `/accesses/<folder_id>/<user_id>/` | Детали права |
| `/statistics/` | Сводные показатели и группировки |

Поиск файлов охватывает имя файла, папки и владельца. Фильтры: ID папки,
ID владельца, максимальный размер, дата загрузки до указанной, только непустые
файлы. Сортировка выбирается из разрешённых значений name/size/date/owner.
При переходе между страницами сохраняются параметры. Некорректные фильтры дают
400; отсутствующий объект — 404; недоступная база — 503. Некорректный номер
страницы возвращает первую, номер вне диапазона — последнюю.

Шаблоны наследуют `templates/base.html`, используют include, url, static и
автоматическое экранирование. CSS, SVG-логотип и JavaScript находятся
в `homepage/static/homepage/`. Кнопка в шапке переключает тему.

### Операции ORM

Для создания и изменения файлов с проверкой доступа и квоты используются
`library.services.save_file`, для удаления — `delete_file`, для выдачи,
изменения и отзыва прав — `set_access`. Обычные веб-страницы доступны для просмотра; операции изменения выполняются
через админ-панель или Python/Django shell.

```python
from library.models import File, Folder
from library.services import save_file, delete_file

folder = Folder.objects.get(pk=1)
file = save_file(File(name="example.txt", folder=folder, size=100), actor_id=1)
file.name = "renamed.txt"
save_file(file, actor_id=1)
delete_file(file.pk, actor_id=1)
```

Сервисы выполняют full_clean и транзакции. Прямые `objects.create/update` —
низкоуровневые операции: они не заменяют проверку прав в сервисах.
PROTECT запрещает удалять папку с файлами и пользователя с папками;
CASCADE удаляет зависимые права. Уникальность имён внутри папки и пары
пользователь/папка закреплена ограничениями БД.

## Назначение и целевая аудитория

Хранение личных файлов, организация по папкам и предоставление доступа другим пользователям.
Проект предназначен для студентов, преподавателей и небольших рабочих групп.

## Предметная область и сущности

- Пользователь: ID, уникальное имя, общая квота в байтах.
- Папка: ID, имя, владелец; у пользователя может быть несколько папок.
- Файл: ID, папка, имя, размер в байтах, дата загрузки.
- Доступ: пользователь-получатель, папка, уровень `read` или `write`.

Файл относится к владельцу папки. Даже если запись добавляет гость с правом `write`,
размер списывается с квоты владельца папки. Владельцу доступны все операции в своей папке.
`read` разрешает просмотр, `write` — просмотр, добавление и удаление файлов.
Только владелец выдаёт и отзывает доступ. Совпадающие имена файлов допустимы в разных папках.

## Возможности ПР3

1. Добавление пользователей и папок; переключение текущего пользователя.
2. Просмотр доступных папок и файлов.
3. Поиск файлов по части имени без учёта регистра, отбор по максимальному размеру.
4. Сортировка по имени, размеру или дате загрузки.
5. Проверка прав и общей квоты, добавление записи файла и удаление с освобождением места.
6. Выдача, изменение и отзыв доступа к папке.
7. Автоматическая загрузка JSON при запуске и сохранение после каждого изменения.
8. Обработка неправильного ввода, неизвестных ID, ошибок чтения/записи и повреждённого JSON.
9. Интроспекция: сигнатура функции каталога через пункт 11.

Сценарий ПР1 сохранён: `can_write`, `has_space`, `upload_file` находятся в `file_storage/rules.py`,
демонстрация доступна через `--demo`. Новая операция `add_file` использует прежние проверки
прав и квоты, но работает с коллекциями объектов и добавляет объект File в каталог.

**Границы учебной версии:** сохраняются метаданные, а не содержимое пользовательских файлов.
Нет вложенных папок, паролей и сетевого сервера; переключение пользователя — учебная имитация.
Все размеры вводятся целыми байтами; пустой файл допустим. 1 МиБ = 1 048 576 байт.
Одновременно следует запускать один экземпляр программы для одного JSON-файла.
Классы предметной области реализованы на ПР3; JSON остаётся совместимым с ПР2.

## Объектная модель ПР3

Контрольная точка до перехода на ООП: коммит `5e8f452` (ПР2), 61 тест проходил,
flake8 не выдавал замечаний. Проект продолжен в том же репозитории.

| Класс | Атрибуты | Методы и назначение |
| --- | --- | --- |
| NamedEntity | id, name | Общая проверка идентификатора и имени, __str__ |
| User | id, name, quota | can_store проверяет остаток квоты; to_dict/from_dict |
| Folder | id, name, owner: User | is_owned_by и allows проверяют права |
| File | id, name, folder: Folder, size, uploaded_at: date | matches выполняет поиск и отбор |
| Access | user: User, folder: Folder, level | allows, change_level; выдача read/write |

User, Folder и File наследуют NamedEntity: каждая сущность имеет идентификатор и имя.
Все четыре предметных класса реализуют конструкторы и собственный __str__.
Меню выводит разные объекты одинаковым вызовом print — это применение полиморфизма.

Связи хранят именно объекты: `file.folder.owner` возвращает User;
`access.folder` ссылается на Folder, а `access.user` — на User.
При загрузке сначала создаются пользователи, затем папки, файлы и права.
Восстановленные ссылки ведут на общие экземпляры из соответствующих коллекций.

Идентификаторы, имена, размеры, квота и ссылки доступны через свойства только для чтения.
Право меняется методом Access.change_level, который проверяет владельца и новый уровень.
Нижнее подчёркивание обозначает внутреннее состояние по соглашению Python.
`@property` используется для чтения атрибутов, `@classmethod` — для восстановления
из словарей, `@staticmethod` — для проверки уровня доступа.

Функции коллекций сохранены: add_user/add_folder/add_file создают и возвращают объекты;
get_record, iter_files, list_files, used_space работают с коллекциями объектов;
set_access координирует изменение прав; delete_file удаляет объект из каталога.
Операции отдельной сущности перенесены в методы User.can_store, Folder.allows,
File.matches и Access.change_level. Чтение/запись JSON и ввод меню остаются функциями.

## Формат данных

На диске один JSON-файл содержит четыре списка словарей. В памяти каталог содержит
списки объектов User, Folder, File и Access. Пример структуры JSON:

```json
{
  "users": [{"id": 1, "name": "ilya", "quota": 104857600}],
  "folders": [{"id": 1, "owner_id": 1, "name": "Учеба"}],
  "files": [{"id": 1, "folder_id": 1, "name": "a.txt", "size": 10,
             "uploaded_at": "2026-10-28"}],
  "accesses": []
}
```

ID — положительные целые числа, размеры и квоты — неотрицательные целые байты.
Ссылки между сущностями, уникальность ID/имён, права и квоты проверяются при чтении и записи.
Перед записью to_data вызывает to_dict объектов и проверяет связи и квоты.
При чтении from_data вызывает конструкторы через from_dict и восстанавливает ссылки.
Посторонний объект с совпадающим ID не принимается вместо связанного экземпляра.
Файлы ПР2 читаются без ручного переноса или изменения формата.

Рабочий `data/catalog.json` исключён из Git; пример включён в репозиторий.
Запись выполняется в соседний временный файл с последующей заменой целевого.

## Упражнение Холодильник

`exercises/fridge.py` реализует учёт продуктов: продукты, партии,
точные дробные количества через Decimal, сроки годности, добавление, поиск, подсчёт,

## Упражнение Змейка

```bash
python -m exercises.snake
```

Локальная пошаговая консольная игра: `w/a/s/d` и Enter задают движение,
Enter без буквы продолжает движение, `q` завершает игру. `O` — голова,
`o` — тело, `*` — яблоко. Границы поля замкнуты. Яблоко увеличивает длину;
разворот в собственное тело запрещён, столкновение завершает игру,
заполнение всего поля означает победу.

GameObject — общий класс, Snake и Apple наследуют его; SnakeGame объединяет объекты,
управляет ходами и счётом. Это локальное упражнение по теме «Изгиб Питона»,
а не точная копия закрытого задания: графический интерфейс и прохождение
автотестов платформы здесь не заявляются.
