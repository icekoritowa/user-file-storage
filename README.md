## ПР7 — SQLite и SQL

Веб-приложение получает данные из `data/storage.sqlite` через стандартный
модуль sqlite3. Django ORM не используется. Консольное приложение продолжает
работать с JSON. Изменения JSON попадают в веб-версию после явного импорта:

```bash
python3 -m db.import_json data/catalog.json
```

Для восстановления примера: `python3 -m db.import_json data/example.json`.
Импорт заменяет содержимое таблиц в транзакции, повторный запуск не создаёт
дубликатов. Перед импортом JSON проходит проверки связей, квот и типов.
SQLite-файл с данными примера включён в репозиторий. Для своей базы можно указать
`--database /путь/storage.sqlite` при импорте и переменную `STORAGE_DATABASE`
при запуске сервера. JSON автоматически не синхронизируется с SQLite.

Схема находится в `sql/schema.sql`, запросы — в `sql/queries.sql`, подключение —
в `db/database.py`, импорт — в `db/import_json.py`. Внешние ключи включаются
при каждом подключении. Пользователи, папки и файлы имеют целочисленные PK;
у доступа составной ключ `(user_id, folder_id)`. Ссылки защищены FK, размеры
и квоты — CHECK, имена внутри папки — UNIQUE. Необязательный email допускает
NULL. Даты хранятся в ISO-формате TEXT, размеры — в байтах INTEGER.

Страница `/statistics/` выводит результаты 12 запросов: списки пользователей
и папок, поиск файлов по имени/размеру/дате, права записи, файлы с владельцами,
выданный доступ, агрегаты файлов и квот, группировку по папкам с HAVING,
папки с достаточным свободным местом, группировку по датам, пользователей
без email. Поиск поддерживает LIMIT 20 и OFFSET. Параметры передаются через
`?`, результаты получаются как sqlite3.Row. Свободное место рассчитывается
по всем папкам владельца, а не только по выбранной папке.

Запуск: `bash run_web.sh`. Проверки: `python manage.py check`,
`python -m pytest -q`, `python -m flake8`.

## ПР6 — шаблоны Django и статические файлы

Веб-слой Django 5.2.x из ПР5 переведён на Django Template Language (DTL).
Классы, JSON и консольное приложение ПР3 продолжают работать. Веб-страницы
показывают каталог; формы, вход пользователей, ORM и база данных остаются
для следующих работ. Сейчас это локальный учебный просмотр
всего каталога, включая сведения о правах, без проверки личности посетителя.

### Быстрый запуск на Mac

В терминале из папки проекта:

```bash

```

### Адреса и приложения

| Адрес | Страница | View |
| --- | --- | --- |
| `/` | Главная и навигация | homepage.views.index |
| `/folders/` | Список папок | library.views.folders |
| `/folders/<int:folder_id>/` | Папка, её файлы и квота владельца | library.views.folder_detail |
| `/files/` | Список файлов | library.views.files |
| `/files/<int:file_id>/` | Имя, размер, дата, папка и владелец | library.views.file_detail |
| `/accesses/` | Выданные права read/write | permissions.views.accesses |
| `/accesses/<int:folder_id>/<int:user_id>/` | Право пользователя на папку | permissions.views.access_detail |

`manage.py` — команды Django. `storage_web/settings.py` — настройки,
`storage_web/urls.py` распределяет URL через include. Приложения homepage, library
и permissions зарегистрированы в INSTALLED_APPS; у каждого собственные apps.py,
urls.py и views.py. Файлы wsgi.py/asgi.py содержат точки входа сервера.
Отдельное приложение пользователей пока не требуется: данные User отображаются
через владельцев папок и получателей доступа. Моделей ORM и базы данных на ПР6 нет.

### От JSON к HTTP-ответу

Запрос → корневой URLconf → URLconf приложения → view → загрузка JSON прежней
функцией load_catalog → объекты User/Folder/File/Access → context → render → шаблон → HTTP-ответ.
Поиск деталей файла и папки использует get_record; неизвестный ID вызывает Http404.
У Access нет отдельного ID: право определяется парой «папка + пользователь».
Если такого права нет или оно отозвано, страница возвращает 404.

HTML полностью вынесен из Python в шаблоны. Функции page(), link() и модуль
homepage/layout.py удалены. Общие структура, стили, скрипт и подвал находятся
в templates/base.html. Страницы наследуют его через extends и переопределяют
блоки title/content. Навигация, карточка папки, таблица файлов и уровень доступа
подключаются через include. Данные по умолчанию экранируются Django.

В settings.py настроены DIRS, APP_DIRS, STATIC_URL и django.contrib.staticfiles.
Дочерние шаблоны получают объекты в словаре контекста; расчёт свободной квоты
и выбор файлов папки остаются в Python. for/empty выводит коллекции и сообщения
для пустых данных; if выбирает содержимое таблицы и вид уровня read/write.
Фильтры length показывают количество, default задаёт запасное название,
date форматирует дату как день.месяц.год, filesizeformat — размер файла.
Все внутренние переходы используют url и пространства имён homepage/library/permissions.

Собственный CSS оформляет карточки, таблицы, права и мобильную версию.
SVG-логотип, CSS и JavaScript подключаются через static. JavaScript выводит год
и переключает светлую/тёмную тему кнопкой в шапке. Выбор действует до перезагрузки
страницы. Bootstrap 5.3.3 загружается с CDN, собственные стили работают и без интернета.

Для локального запуска при DEBUG=False скрипт run_web.sh передаёт runserver
параметр --insecure, чтобы Django отдавал CSS, JS и логотип, сохраняя собственную
страницу 404. Сервер слушает только 127.0.0.1; этот режим предназначен для разработки.
[Документация Django по статическим файлам](https://docs.djangoproject.com/en/5.2/howto/static-files/).

В версии ПР6 использовался `data/catalog.json`, созданный консольной программой.
Если его нет, показывается `data/example.json` без копирования и записи. Пустой
рабочий каталог остаётся пустым; повреждённый JSON даёт страницу 503 и не заменяется.
Путь можно задать переменной окружения STORAGE_CATALOG:

```bash
STORAGE_CATALOG=/полный/путь/catalog.json python manage.py runserver 127.0.0.1:8000 --insecure
```

До перехода на SQLite каждый запрос перечитывал JSON: сохранённые изменения консольной версии видны
после обновления страницы браузера. Веб-обработчики принимают GET/HEAD; POST даёт 405.
Учебные права отображаются как данные; аутентификация веб-посетителей пока отсутствует.

DEBUG по умолчанию False, ALLOWED_HOSTS разрешает localhost и 127.0.0.1.
Собственный handler404 зарегистрирован в корневом urls.py. Проверить его можно
по `/missing/`, `/files/999/` и `/files/abc/`: первые два случая отличаются поиском
маршрута и объекта, последний не проходит конвертер int. Для технических страниц
отладки запустить с DJANGO_DEBUG=1. SECRET_KEY имеет локальное учебное значение;
для будущего развёртывания предусмотрена переменная DJANGO_SECRET_KEY.

## Назначение и целевая аудитория

Хранение личных файлов, организация по папкам и предоставление доступа другим пользователям.
Проект предназначен для студентов, преподавателей и небольших рабочих групп.

## Предметная область и сущности

- Пользователь: ID, уникальное имя, общая квота в байтах.
- Папка: ID, имя, владелец; у пользователя может быть несколько папок.
- Файл: ID, папка, имя, размер в байтах, дата загрузки.
- Доступ: пользователь-получатель, папка, уровень `read` или `write`.

Файл относится к владельцу папки. Даже если запись добавляет гость с правом `write`,
размер списывается с квоты владельца папки. Владельцу доступны все операции в своей папке.
`read` разрешает просмотр, `write` — просмотр, добавление и удаление файлов.
Только владелец выдаёт и отзывает доступ. Совпадающие имена файлов допустимы в разных папках.

## Возможности ПР3

1. Добавление пользователей и папок; переключение текущего пользователя.
2. Просмотр доступных папок и файлов.
3. Поиск файлов по части имени без учёта регистра, отбор по максимальному размеру.
4. Сортировка по имени, размеру или дате загрузки.
5. Проверка прав и общей квоты, добавление записи файла и удаление с освобождением места.
6. Выдача, изменение и отзыв доступа к папке.
7. Автоматическая загрузка JSON при запуске и сохранение после каждого изменения.
8. Обработка неправильного ввода, неизвестных ID, ошибок чтения/записи и повреждённого JSON.
9. Интроспекция: сигнатура функции каталога через пункт 11.

Сценарий ПР1 сохранён: `can_write`, `has_space`, `upload_file` находятся в `file_storage/rules.py`,
демонстрация доступна через `--demo`. Новая операция `add_file` использует прежние проверки
прав и квоты, но работает с коллекциями объектов и добавляет объект File в каталог.

**Границы учебной версии:** сохраняются метаданные, а не содержимое пользовательских файлов.
Нет вложенных папок, паролей и сетевого сервера; переключение пользователя — учебная имитация.
Все размеры вводятся целыми байтами; пустой файл допустим. 1 МиБ = 1 048 576 байт.
Одновременно следует запускать один экземпляр программы для одного JSON-файла.
Классы предметной области реализованы на ПР3; JSON остаётся совместимым с ПР2.

```bash

```

```bash
python main.py --demo
python -m exercises.fridge

python -m flake8
```

## Объектная модель ПР3

Контрольная точка до перехода на ООП: коммит `5e8f452` (ПР2), 61 тест проходил,
flake8 не выдавал замечаний. Проект продолжен в том же репозитории.

| Класс | Атрибуты | Методы и назначение |
| --- | --- | --- |
| NamedEntity | id, name | Общая проверка идентификатора и имени, __str__ |
| User | id, name, quota | can_store проверяет остаток квоты; to_dict/from_dict |
| Folder | id, name, owner: User | is_owned_by и allows проверяют права |
| File | id, name, folder: Folder, size, uploaded_at: date | matches выполняет поиск и отбор |
| Access | user: User, folder: Folder, level | allows, change_level; выдача read/write |

User, Folder и File наследуют NamedEntity: каждая сущность имеет идентификатор и имя.
Все четыре предметных класса реализуют конструкторы и собственный __str__.
Меню выводит разные объекты одинаковым вызовом print — это применение полиморфизма.

Связи хранят именно объекты: `file.folder.owner` возвращает User;
`access.folder` ссылается на Folder, а `access.user` — на User.
При загрузке сначала создаются пользователи, затем папки, файлы и права.
Восстановленные ссылки ведут на общие экземпляры из соответствующих коллекций.

Идентификаторы, имена, размеры, квота и ссылки доступны через свойства только для чтения.
Право меняется методом Access.change_level, который проверяет владельца и новый уровень.
Нижнее подчёркивание обозначает внутреннее состояние по соглашению Python.
`@property` используется для чтения атрибутов, `@classmethod` — для восстановления
из словарей, `@staticmethod` — для проверки уровня доступа.

Функции коллекций сохранены: add_user/add_folder/add_file создают и возвращают объекты;
get_record, iter_files, list_files, used_space работают с коллекциями объектов;
set_access координирует изменение прав; delete_file удаляет объект из каталога.
Операции отдельной сущности перенесены в методы User.can_store, Folder.allows,
File.matches и Access.change_level. Чтение/запись JSON и ввод меню остаются функциями.

## Формат данных

На диске один JSON-файл содержит четыре списка словарей. В памяти каталог содержит
списки объектов User, Folder, File и Access. Пример структуры JSON:

```json
{
  "users": [{"id": 1, "name": "ilya", "quota": 104857600}],
  "folders": [{"id": 1, "owner_id": 1, "name": "Учеба"}],
  "files": [{"id": 1, "folder_id": 1, "name": "a.txt", "size": 10,
             "uploaded_at": "2026-10-28"}],
  "accesses": []
}
```

ID — положительные целые числа, размеры и квоты — неотрицательные целые байты.
Ссылки между сущностями, уникальность ID/имён, права и квоты проверяются при чтении и записи.
Перед записью to_data вызывает to_dict объектов и проверяет связи и квоты.
При чтении from_data вызывает конструкторы через from_dict и восстанавливает ссылки.
Посторонний объект с совпадающим ID не принимается вместо связанного экземпляра.
Файлы ПР2 читаются без ручного переноса или изменения формата.

Рабочий `data/catalog.json` исключён из Git; пример включён в репозиторий.
Запись выполняется в соседний временный файл с последующей заменой целевого.

Локальная пошаговая консольная игра: `w/a/s/d` и Enter задают движение,
Enter без буквы продолжает движение, `q` завершает игру. `O` — голова,
`o` — тело, `*` — яблоко. Границы поля замкнуты. Яблоко увеличивает длину;
разворот в собственное тело запрещён, столкновение завершает игру,
заполнение всего поля означает победу.

GameObject — общий класс, Snake и Apple наследуют его; SnakeGame объединяет объекты,
управляет ходами и счётом. Это локальное упражнение по теме «Изгиб Питона»,
а не точная копия закрытого задания: графический интерфейс и прохождение
автотестов платформы здесь не заявляются.
