# Система хранения пользовательских файлов

Индивидуальный сквозной проект по дисциплине «Технологии разработки приложений на базе фреймворков».

**Автор:** Огарков Илья Евгеньевич. **Группа:** ЭФБО-10-24. **Год:** 2026.

Репозиторий: https://github.com/icekoritowa/user-file-storage

## Назначение и целевая аудитория

Хранение личных файлов, организация по папкам и предоставление доступа другим пользователям.
Проект предназначен для студентов, преподавателей и небольших рабочих групп.

## Предметная область и сущности

- Пользователь: ID, уникальное имя, общая квота в байтах.
- Папка: ID, имя, владелец; у пользователя может быть несколько папок.
- Файл: ID, папка, имя, размер в байтах, дата загрузки.
- Доступ: пользователь-получатель, папка, уровень `read` или `write`.

Файл относится к владельцу папки. Даже если запись добавляет гость с правом `write`,
размер списывается с квоты владельца папки. Владельцу доступны все операции в своей папке.
`read` разрешает просмотр, `write` — просмотр, добавление и удаление файлов.
Только владелец выдаёт и отзывает доступ. Совпадающие имена файлов допустимы в разных папках.

## Возможности ПР2

1. Добавление пользователей и папок; переключение текущего пользователя.
2. Просмотр доступных папок и файлов.
3. Поиск файлов по части имени без учёта регистра, отбор по максимальному размеру.
4. Сортировка по имени, размеру или дате загрузки.
5. Проверка прав и общей квоты, добавление записи файла и удаление с освобождением места.
6. Выдача, изменение и отзыв доступа к папке.
7. Автоматическая загрузка JSON при запуске и сохранение после каждого изменения.
8. Обработка неправильного ввода, неизвестных ID, ошибок чтения/записи и повреждённого JSON.
9. Интроспекция: справка по docstring функции каталога через пункт 11.

Сценарий ПР1 сохранён: `can_write`, `has_space`, `upload_file` находятся в `file_storage/rules.py`,
демонстрация доступна через `--demo`. Новая операция `add_file` использует прежние проверки
прав и квоты, но работает с коллекциями и действительно добавляет запись в каталог.

**Границы учебной версии:** сохраняются метаданные, а не содержимое пользовательских файлов.
Нет вложенных папок, паролей и сетевого сервера; переключение пользователя — учебная имитация.
Все размеры вводятся целыми байтами; пустой файл допустим. 1 МиБ = 1 048 576 байт.
Одновременно следует запускать один экземпляр программы для одного JSON-файла.
Классы предметной области и декораторы приложения отложены до ПР3.

## Запуск

Python 3.10 или новее. Приложение использует только стандартную библиотеку.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python main.py
```

Windows: вместо `source` выполнить `.venv\Scripts\activate`.
При первом запуске каталог пуст: пункт 2 создаёт первого пользователя и выбирает его;
пункт 5 создаёт папку; пункт 7 добавляет запись файла. Пункт 0 завершает работу.

Для подготовленных данных (копировать пример только в начале, чтобы не затереть свою работу):

```bash
cp data/example.json data/catalog.json
python main.py
```

В примере пользователи `ilya` (ID 1) и `guest` (ID 2), папки «Учеба» и «Личное».
Гость может читать только «Учеба». Все пункты меню проверены автоматизированным сценарием.

```bash
python main.py --data /tmp/my-storage.json
python main.py --demo
python -m exercises.fridge
python -m pytest -q
python -m flake8
```

Для меню предусмотрены EOF (Ctrl+D, в Windows Ctrl+Z) и Ctrl+C.
При повреждённом JSON программа выводит причину и завершает работу, не заменяя данные пустыми.
При ошибке сохранения предыдущий каталог остаётся в памяти и на диске.

## Формат данных

Один JSON-файл содержит четыре списка словарей. Пример структуры:

```json
{
  "users": [{"id": 1, "name": "ilya", "quota": 104857600}],
  "folders": [{"id": 1, "owner_id": 1, "name": "Учеба"}],
  "files": [{"id": 1, "folder_id": 1, "name": "a.txt", "size": 10,
             "uploaded_at": "2026-10-28"}],
  "accesses": []
}
```

ID — положительные целые числа, размеры и квоты — неотрицательные целые байты.
Ссылки между сущностями, уникальность ID/имён, права и квоты проверяются при чтении и записи.
Рабочий `data/catalog.json` исключён из Git; пример включён в репозиторий.
Запись выполняется в соседний временный файл с последующей заменой целевого.

## Конструкции Python и качество

Списки и словари хранят сущности; множество используется для ID папок и проверки уникальности;
кортежи — для пар пользователь/папка. `for` обрабатывает записи, `while` управляет меню.
`iter_files` — генератор с `yield`; `lambda` задаёт ключ сортировки.
`getattr`, `callable` и `__doc__` реализуют интроспекцию.
Основные функции снабжены аннотациями типов и docstring. Состояние передаётся параметром,
а не хранится в изменяемых глобальных переменных. Работа с файлами использует `with`,
ошибки обрабатываются через `try/except`, временный файл очищается в `finally`.

Проверки включают права, квоты, поиск, сортировку, сохранение/перезапуск,
некорректный JSON, отказ записи, все пункты меню и упражнение «Холодильник».
Результаты: [verification.txt](docs/pr2/verification.txt).
Отладка: [debugging.md](docs/pr2/debugging.md).

## Упражнение Холодильник

`exercises/fridge.py` содержит локальное решение требований из PDF: продукты, партии,
точные дробные количества через Decimal, сроки годности, добавление, поиск, подсчёт,
отбор просроченного, чтение и запись JSON. День окончания срока считается допустимым:
партия просрочена, если дата окончания строго раньше даты проверки.
JSON хранит количества строками, чтобы не терять точность дробей.

Это проверенное локальное упражнение, а не заявление о прохождении автопроверки
Яндекс Практикума: точный закрытый интерфейс заданий и аккаунт курса недоступны.
[Чек-лист ПР2](docs/pr2/checklist.md) отделяет реализацию от неподтверждённых материалов курса.
